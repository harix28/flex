# Maintenance Priority Policy Specification

Version: 1.0 · Updated: 2026-10-26 · Status: Phase 6 Implemented (Experimental Policy `v1-experimental`)

## Core Concepts & Disclaimer

Meridian Sentinel separates machine degradation estimation into three distinct concerns:
1. **Model Output**: Estimated remaining operational flight cycles ($\widehat{\text{RUL}}$) generated by the verified neural network.
2. **Policy Output**: Transparent, rule-based maintenance priority band and plain explanation evaluated against configurable cycle thresholds.
3. **Failure Probability & Component Fault Attribution**: Explicitly **unavailable** (`null`).

> [!WARNING]
> **DISCLAIMER: EXPERIMENTAL SIMULATION THRESHOLDS ONLY**  
> Priority thresholds in this policy are experimental parameters designed for turbofan simulation testbeds (C-MAPSS FD001). They are **not** manufacturer-approved operating limitations, airworthiness directives, or safety-critical maintenance dispatch criteria. Operational decisions must not rely on experimental synthetic thresholds without physical validation and regulatory certification.

---

## Priority Bands and Threshold Rules

Policy version: `v1-experimental`

| Priority Band | Cycle Threshold | Plain English Explanation | Action Required |
| :--- | :--- | :--- | :--- |
| **`urgent`** | $\widehat{\text{RUL}} \le 15.0\text{ cycles}$ | "Estimated RUL $\le 15$ cycles: urgent maintenance review recommended before dispatch" | Priority inspection scheduling; halt dispatch |
| **`high`** | $15.0 < \widehat{\text{RUL}} \le 35.0\text{ cycles}$ | "Estimated RUL between 15 and 35 cycles: high priority / schedule maintenance inspection" | Plan service interval within upcoming maintenance shift |
| **`medium`** | $35.0 < \widehat{\text{RUL}} \le 75.0\text{ cycles}$ | "Estimated RUL between 35 and 75 cycles: medium priority / monitor trend across flights" | Track degradation rate across successive cycles |
| **`low`** | $\widehat{\text{RUL}} > 75.0\text{ cycles}$ | "Estimated RUL $> 75$ cycles: low priority / normal operational tracking" | Normal operational monitoring |
| **`unknown`** | Unavailable attempt or missing prediction | "Latest attempt unavailable (`{reason}`); priority unknown" / "No predictions recorded; priority unknown" | Investigate telemetry pipeline; backfill missing cycles |

### Threshold Validation Constraints
1. $0 < \text{urgent\_max\_cycles} < \text{high\_max\_cycles} < \text{medium\_max\_cycles} < \infty$.
2. All thresholds are strictly positive finite numbers.
3. Units are strictly cycles.

## Ranking & Outdated Semantics

The fleet maintenance priority endpoint (`GET /api/v1/maintenance-priorities`) ranks all active machines in an organization using a deterministic 7-tier ranking structure:

### Ranking Order:
1. **Urgent current predictions** ($\text{RUL} \le 15$ cycles), ordered by ascending RUL.
2. **High priority current predictions** ($15 < \text{RUL} \le 35$ cycles), ordered by ascending RUL.
3. **Medium priority current predictions** ($35 < \text{RUL} \le 75$ cycles), ordered by ascending RUL.
4. **Low priority current predictions** ($\text{RUL} > 75$ cycles), ordered by ascending RUL.
5. **Outdated predictions** (telemetry has advanced past the prediction cutoff cycle), ordered by ascending historical RUL.
6. **Unavailable latest attempts** (insufficient history, gaps in history, unsupported model), sorted deterministically.
7. **No predictions recorded** (unpredicted active machines).

*Deterministic tie-breaking*: By `asset_code ASC`.

### Critical Integrity Rules:
- **No Masquerading**: An unavailable latest attempt (e.g. telemetry gap) is **never** replaced with an older successful prediction. Doing so would present a degraded or unmeasured machine as healthy.
- **Outdated Visibility**: If the database contains observation cycles beyond the prediction's cutoff cycle ($C_{\text{latest}} > C_{\text{pred}}$), the prediction is marked `is_outdated = true` and `is_current = false`. It is ranked in the outdated tier and carries an explicit explanation detailing the discrepancy.
- **No Fabricated Risk Scores**: Meridian Sentinel refuses to fabricate a pseudo-statistical 0–100% "health score" from single point predictions without calibrated Bayesian or conformal uncertainty bounds.

## Maintenance Priority API

### Endpoint:
`GET /api/v1/maintenance-priorities?limit=50&offset=0&priority_band=urgent`

- **Permissions**: `predictions.read` (all authenticated tenant members).
- **Query Parameters**:
  - `limit`: Integer (1..100, default 50).
  - `offset`: Integer ($\ge 0$, default 0).
  - `priority_band`: Optional filter (`urgent` | `high` | `medium` | `low` | `unknown`).
